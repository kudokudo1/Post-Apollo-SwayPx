## IMPLEMENTATION

Prior to M32p, M32m could observe physically selected native Company identity, private Wayland intent and viewport, the M28b kernel pidfd actor, installed ELF and compiled digest, while M32o separately provided an inert five-second candidate ledger. There was **no internal bridge** between them.

M32p adds two **compositor-only** functions to the existing real Company protocol:
- `stage_director_company_vector_protocol_candidate_reserve_current(view, lineage)`: accepts a real compositor-owned mapped `sway_view` and native lineage, re-observes the XDG root and runs **M32m preflight**; only its final `OPERATOR_LEASE_ABSENT` candidate status can feed M32o's exact host/actor/process selection snapshot. Time comes from compositor `CLOCK_BOOTTIME`, never from QML or client input. Reservation remains **inert**.
- `stage_director_company_vector_protocol_candidate_probe_current(view, lineage)`: performs fresh XDG/host/intent/viewport/pidfd/ELF/digest checks on every probe. Failed native re-observation destroys the previous candidate; even a valid candidate remains completely nonauthorizing.

M32p also revokes an old candidate upon any **current bound** viewport report (including malformed reports), selected CLOSE, or full protocol/host/pidfd teardown. Stale reporters cannot revoke another owner's candidate. The M32m protocol still revokes visible scenes before clearing provenance.

**No public Wayland requests, operator issuer, launch custody, production digest pin, QML launch UI, scene setters or seat privileges are added.** Normal build keeps the compiled digest empty, so this reserve path cannot succeed with real current production observations. Even if a future approved manifest matched, M32o explicitly returns zero scene/input/popup/focus rights.

## VERIFY

The dedicated M32p source-contract and negative-mutation test verifies actual source observations, exact native object fields, status/authority checks, monotonic clock, and revocation order. It also reruns M32o's native C lifecycle tests for epoch replay, timeout, stale actor, pidfd/process and identity loss. The workflow compiles ordinary and private CI-only SwayPX variants to detect regressions.

These checks prove source contract + compilation, **not** physical operator approval, a live mapped Company protocol session, installed Fedora runtime, or scene authorization.

## WATCH OUT FOR

The remaining blocker is genuine **independent authorization**: the existing F11 physical Company host selection is not explicit approval of a separate Qt actor or its launch. The Company-owned launch request and held kernel pidfd still do not prove that the operator authorized the exact executable/dependency set. A later compositor-owned issuer must bind a real operator action, approved executable hash, trusted launch custody, exact native generation, output and viewport, TTL, and revocation. Do not derive approval from a matching app-id, source status or QML boolean.

No physical input should be imitated by CI. Production scene activation and desktop modifications require separate operator approval.
