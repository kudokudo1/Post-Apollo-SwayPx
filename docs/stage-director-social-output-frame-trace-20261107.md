## IMPLEMENTATION

The first native move/resize demonstrations established paired rectangle updates before the transaction commit, and subsequent tests established sampled real rendered pixel fidelity. **They did not measure what SwayPX actually submitted to its output device on each repaint.** This patch adds a fourth **test-only** C overlay file, `sway/desktop/output.c`, inside the disposable GitHub runner source copy. The production checkout remains unchanged.

A narrowly environment-guarded function runs only **after a successful call to `wlr_output_commit_state`**. It independently retrieves the exact current host/guest native container IDs and PIDs from the existing protected CI lease, rejects missing/unmapped/wrong-workspace clients, then reads both containers' **current** rectangles and both scene-tree node positions. It records a strictly increasing output-commit sequence. The host rectangle and guest rectangle must retain Social rail=110 and inset=1, while the actual scene-node positions must maintain the same relative offset.

The real Wayland CI runtime checks every recorded successful output commit for a coherent host/guest rectangle and scene relationship, a matching exact lease, increasing frame IDs, at least sixteen committed samples and at least eight distinct host positions. Any `SPLIT`, invalid frame, stale actor, missing evidence or under-sampled run is a failure. The output commit probe **does not move windows, change scene stacking, alter scene pixels, or grant any new authority**.

The existing #102 screenshot streams remain independently required: real native bidirectional moves and paced resizes; 38 RGB checks per usable screenshot; transition samples excluded; prior eight paused in-flight screenshots; guest-over-chassis layering; unrelated client protections; stale lease refusal; clean temporary `/dev/udmabuf` ACL rollback.
