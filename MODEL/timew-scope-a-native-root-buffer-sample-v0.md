## IMPLEMENTATION // Actual deeper renderer signal

The pinned `flake.lock` [SceneFX revision `26200c5d9fa947a1d3b0935d3f9237229cd3e5ba`](https://github.com/wlrfx/scenefx/tree/26200c5d9fa947a1d3b0935d3f9237229cd3e5ba) exposes **`wlr_scene_buffer.events.output_sample`**, carrying `wlr_scene_output_sample_event` (scene output, `direct_scanout` flag, release timeline/point). This is significantly more specific than SwayPX's frame-done `wlr_scene_output_for_each_buffer` traversal (#189). The pinned SceneFX implementation emits the signal immediately **after `fx_render_pass_add_texture`** for compositing, or **after successful direct-scanout state preparation/test**. This indicates a specific source scene buffer was sampled into a render pass or chosen for a candidate scanout. The event is not itself GPU completion, accepted output commit, final output PRESENT or terminal client frame.

`tests/timew/ci_overlay_real_root_sample.py` adds **temporary GitHub-runner-only hooks**. Immediately before the original `sway/desktop/output.c` call to `wlr_scene_output_build_state`, it traverses the pending output's scene buffers to attach one `wl_listener` to the exact **mapped candidate XDG root `wlr_surface`**, requiring `wlr_scene_surface_try_from_buffer(buffer)->surface == ci_view->surface` and the correct output primary scene. Foreign views, overlays, popups, subsurfaces and unrelated XDG roots cannot match. The native `output_sample` signal callback rechecks the same true view/root and output, active workspace, private candidate and live lifetime, then logs real SceneFX `direct_scanout=0/1` and the local observed post-scene instruction. A scene-buffer destroy listener detaches before free. The already-existing actual XDG unmap path synchronously detaches both listeners, writes the sample count and seals all diagnostic state. There is **no callback retained after unmap**, and all data is process-local and non-credentialed.

## VERIFY // What the signal can and cannot establish

**If native CI passes**, the new supported claim is: **SceneFX emitted an actual native `output_sample` for the exact mapped XDG ROOT surface's scene buffer on the correct output while building an output render/scanout state**. Parent #193 separately proves real output commit↔PRESENT serial matches. Those together provide **stronger source-side inclusion evidence**, but still not all that a protected final per-view settlement would require:

- The signal is emitted when adding texture options to a render pass or preparing direct scanout, **not when the selected XDG buffer's pixels are verifiably displayed**. A render pass can fail or lose to later effects, occlusion and subsequent output submission.
- We do not bind a particular immutable `wl_surface` committed buffer generation or client configure ACK to the SceneFX sample and exact output commit serial through an accepted lifetime/epoch protocol. One local instruction sequence is not a protected packet.
- `output_event->presented` and `commit_seq` identify the output submission only. They are not proof of the exact selected XDG's latest final buffer, animation completion, output-fit or final settled rectangle.
- No independently authenticated operator-selected seat/input origin, installed SwayPX producer/release/host, source signing, C5 full intent **one-use durable PRE-ACTION SPENT** or TimeW canonical signed per-step receipt and crash UNKNOWN reconciliation is implemented.

All output is deliberately `accepted_output_commit=UNVERIFIED selected_xdg_final_presented=UNVERIFIED configure_ack=UNVERIFIED source=UNENROLLED c5_spent=NONE receipt=NONE move=OFF retry=OFF authority=NONE`. Even a positive `output_sample` plus a matched output PRESENT must not grant MOVE, retry, undo or Restore.
