# SECURITY // POST-APOLLO FORK

Security reports are welcome when they concern an actual security or privacy risk in this fork.

## Report privately when possible

If GitHub offers a private **Report a vulnerability** option for this repository, use it.

If no private reporting channel is available, open a minimal issue asking the repository owner for a private security contact. Do **not** post exploit details, credentials, private data, or a working proof of concept publicly.

Relevant reports may include:

- command execution or injection;
- privilege or authorization failures;
- unsafe file or network behavior;
- input-routing or cross-seat isolation failures;
- dependency or supply-chain compromise;
- leaked credentials or sensitive data;
- fork-specific regressions that create a security boundary failure.

For vulnerabilities that also affect the upstream project, coordinated disclosure to the upstream maintainers may be appropriate.

## Good-faith research

Do not access data that is not yours, disrupt other users, perform destructive testing, or publicly disclose an issue before maintainers have had a reasonable chance to investigate.

There is no guaranteed response-time SLA and no standing bug-bounty promise.
